directus-main — system architecture

Four workspaces, one real dependency order — not name-based guessing.

Every dependency below was checked against the real Directus project's actual package.json fields before anything was built, not assumed from what a package's name sounds like it should need. That's how packages/constants — not packages/types — turned out to be the actual zero-dependency leaf. See Auth & Request Flow for how app/ actually uses these packages at runtime.

Real CI bug, found and fixed: the workflow originally ran Lint/Test before Build. That passed locally (where a previous yarn build had already left dist/ on disk) but failed on a fresh CI checkout, because packages/stores importing from @directus/constants resolves against dist/index.js — which doesn't exist until Build runs. Fixed by moving Build right after Format, and verified by deleting all local dist/ output and re-running the full suite in the new order before trusting it.
